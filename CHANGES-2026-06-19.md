## Changes — June 19, 2026 (Celebration system fixes)

Fixed the guest celebration feature, which wasn't displaying personalized
messages on cabin screens. Four separate bugs were found and fixed:

### 1. Celebrations saved under the wrong field names (`celebration.js`)
JotForm sends generic field names (`q2_q2_dropdown0`, `q3_q3_dropdown1`, etc.),
not descriptive ones. The webhook handler was searching for keywords like
"cabin" in the field names and finding nothing, so it returned "cabin required"
and never saved. Now it reads fields by their actual JotForm position
(q2 = cabin, q3 = occasion, q4 = guest name, q5 = message, q6 = action),
with keyword matching as a fallback.

### 2. Long / multi-part messages were truncated (`celebration.js`)
The multipart form parser used a lazy regex that could cut a value short.
It now splits on the real multipart boundary from the Content-Type header,
and when merging JotForm's `rawRequest` JSON it keeps the LONGER value per
field so a truncated copy can never overwrite a complete one. A parse failure
is now logged (`CELEBRATION rawRequest parse failed: ...`) instead of being
silently swallowed.

### 3. Every cabin fetched Huckleberry's celebration (`index.html`) — the big one
`loadCelebration()` read `window._cabinKey`, but that variable was never
assigned anywhere, so it always fell back to the default `'huckleberry'`.
Result: every cabin's screen fetched Huckleberry's celebration and ignored
its own `?cabin=` parameter. Huckleberry appeared to "work" only because it
matched the default. Fixed by reading the cabin from the URL (and `init()`
now sets `window._cabinKey` so the auto-clear DELETE also targets the right cabin).

### 4. Surprises set before check-in were hidden as "stale" (`index.html` + `guest.js`)
The expiry logic marked a celebration stale if it was set before the guest's
arrival date — but hosts set up surprises ahead of check-in on purpose. Also,
`guest.js` only returned a formatted departure string ("June 22"), which
`index.html` had to reverse-engineer (lossy). Now `guest.js` returns raw ISO
dates (`departureRaw`, `arrivalRaw`) and `index.html` uses them directly.
A celebration is only hidden once today is past the guest's checkout.

### New operator pages (repo root)
- `status.html` — fleet dashboard. Shows all 8 cabins at a glance: which have a
  personalized message live now, which have a guest checked in with no message
  set (opportunity), which are stored-but-hidden, and which are empty.
  Live at `/status.html`.
- `cabin-links.html` — master reference of every screen URL, admin page,
  lock sync link, JotForm form + per-cabin prefill links. Live at `/cabin-links.html`.

### Key lesson
The test/preview version of the JotForm does NOT fire the webhook the same way —
always test celebrations with the live published form link, not the preview.
